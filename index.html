About

Why state matters

I like systems that make their logic visible. A digital locker that only opens when its internal state allows it. A booking page that only shows the next step once the current one is done. That way of thinking started with digital design — building a Moore machine, where the output depends purely on the current state, nothing hidden, nothing guessed.

It carried straight over into web development. Building a train ticket booking system in React meant thinking in the same terms: what state is this screen in, what triggers the next one, what should never be allowed to happen. I'm looking for an internship where I can keep working at that overlap — writing code that's as deliberate as a state diagram.
